Edit 1 — `changed_files(root, base)` gains a returncode check and a walk-root filter. Capture the
completed process, and if its `returncode` is non-zero raise `SystemExit` with a message that names
the string `judge-packets: git diff failed for BASE` followed by the base value and the captured
stderr. This closes D-16's third vacuous-green channel, where a typo'd BASE or a non-repo cwd
returns an empty stdout and the script reports 0 hunks with exit 0.

Then scope the returned paths to the walk root. `git diff --name-only` returns repo-root-relative
paths regardless of `cwd`, so filtering on the `.md` suffix alone lets `.planning/*.md` and
`.claude/*.md` through — D-16 proved this by observing `.planning/REQUIREMENTS.md` in the working

and keep a changed path only when the relative walk root is `.` or the path equals it or begins with
it followed by a forward slash. Keep the existing `.md` suffix test as well.

Edit 2 — `packets()` resolves each changed path against the REPOSITORY root, not the walk root.

already `docs/…`, so `root / f` becomes `docs/docs/…` and `p.exists()` is false for every entry.
D-16 isolated the fault precisely here — `git_show` is correct from any cwd, only `p.exists()`
fails. Resolve the repository root once inside `packets()` (or thread it through from
`changed_files`) and build `p` from it.

Edit 3 — the `--chunk-file` branch gains an empty-bin guard. After the greedy balance loop, write a
packet file only for a bin whose length is greater than zero, and print one summary line before
returning that contains the literal token `judge-packets:` followed by the total hunk count, the
total file count, the requested bin count, and the non-empty bin count. This closes D-16's second
defect, where `--chunks N` pre-allocates `N` bins with no guard so a judge can be dispatched on an

Preserve the existing `--context`, `--risk` and no-`--chunk-file` JSON-to-stdout behaviours exactly.

contents reproducible across runs.
