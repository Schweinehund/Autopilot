<deviation_note>
**The expected triple is re-derived here and it is not the number the context document carries.**

The context document's arithmetic is one audit check plus one hundred and five chain members plus two
extra members plus one harness check plus one self check, totalling one hundred and ten. That
derivation assumed the apex carries no check beyond the predecessor's five categories.

This plan assigns the frozen carve-out successor to the apex, because the apex is this phase's own
successor validator and a standalone file for one check would be a sixteenth validator nobody runs.
That adds exactly one check. The predecessor's own rule is that **every count is re-derived, never
copied** — a sibling apex shipped three stale runtime strings by ignoring it — so the triple is
recomputed rather than carried:

- **111 / 0 / 0** once this phase's verification document exists.
- **110 / 0 / 1** before it exists.
- **109 / 1 / 1** if the apex is run before the new harness lands, which is why ordering is harness,
  then leaves, then apex.

State this derivation in the apex's own header comment, with the formula, so the next reader
recomputes rather than trusts.
</deviation_note>
