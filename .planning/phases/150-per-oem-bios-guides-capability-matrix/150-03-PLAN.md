**What the research measured on 2026-08-25:** Lenovo's own support KB `ht036206`

`Reset forgotten supervisor password - If you forget your supervisor password, Lenovo cannot reset your password. You must take your computer to a Lenovo Service Provider to have the system board replaced.`

**The consequence, which this plan encodes:**

1. The lost-supervisor-password case is a **documented destructive path**, not an absence. It ships as
   fact, with its source and date, in Lenovo's Recovery section. The D-53 three-part
   documented-silence shape does **not** apply to it.
2. D-55's bar against an unsourced system-board sentence **stands unchanged for every other case** —
   most importantly for the certificate-private-key gap (U-2), where Lenovo has said nothing. Writing
   a board-replacement sentence there would be exactly the unsourced inference D-55 exists to bar.
3. The matrix's Lenovo lost-password cell is therefore a **sourced value**, not
   `Not documented by vendor`. Plan 04 carries that.
4. The Lenovo Recovery section's shape becomes **one documented destructive path plus one documented
   silence**, not two silences.

`150-RESEARCH.md` records this as Assumption A1, with its risk stated: the KB is a general ThinkPad
password page rather than a fleet-management page, and no TBCT V2 documentation was found that
overrides it. Ship it as Lenovo's own statement with its source, not as a fleet-specific guarantee.

**`## Authentication`** — Per D-76, sub-divide by auth model, and say up front that the choice is
model-generation-gated.

key material, **never in a vendor cloud**. Ship the migration breaking change as a callout:
`Previously created INI files from the HTA version which contain an encrypted password are not compatible with the new Think BIOS Config Tool V2 due to changes in encryption methods.`
State the consequence — anyone migrating from the older tool must regenerate every INI.

*Certificate-based BIOS authentication.* Replaces the plain-text supervisor password with a digital
signing certificate, removing the need to ship passwords in scripts. Two enrollable certificates, the

and with Subject and Issuer viewable there. Per Assumption A3, do **not** present those reset options
as a bypass for a lost private key: no page found states whether they are reachable without the
key-based unlock flow, and presenting them as a bypass would be an unsourced recovery path.

(published 2025-11-04): the certificate tool can sign commands using keys stored in Azure Key Vault,
which removes the need to distribute private keys. State the consequence in this corpus's own prose,
and label the comparative claim as this corpus's inference exactly as `00-overview.md` already does —
Lenovo is the only one of the three vendors whose signing key can sit in infrastructure the customer
owns outright, and therefore under the customer's own access control, audit logging and key rotation
policy. Lenovo makes no such comparative claim.
