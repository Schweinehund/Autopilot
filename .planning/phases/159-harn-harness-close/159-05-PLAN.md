missing chain member is a hard FAIL, so all five must exist before the apex plan runs. A leaf that

attribution rule exists to prevent.

and a recorded failability proof for every needle in all three.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository corpus to validator verdict | A leaf's verdict is a claim about the corpus; a wrongly-rooted or empty walk turns a real regression into a green. |
| leaf process to spawned tool | One leaf launches a Python self-test as a child process. |
| line-ending representation to byte-length and count needles | A checkout with converted line endings changes byte lengths and can change counts. |

| T-159-21 | Information Disclosure | a vacuously green corpus-wide zero | high | mitigate | Every corpus-wide negative carries the corpus-floor sentinel as a hard FAIL below 250 files, the floor literal's presence is a grep-based acceptance command, and the live documentation file count is measured and asserted above the floor. |
| T-159-22 | Repudiation | a needle attributed to the wrong phase | high | mitigate | Every corpus-wide zero carries a full boundary series proving the transition landed inside the owning phase's window and stayed stable at every later boundary; the predecessor's misattributions are enumerated and superseded in writing. |
| T-159-23 | Elevation of Privilege | the one permitted spawn | medium | mitigate | Argument-array form only, asserted by a grep acceptance command; the spawn is paired with a fail-loud presence check so a missing tool cannot be laundered into a skip. |
| T-159-24 | Tampering | a needle that cannot fail | medium | mitigate | Every needle is perturbed in a scratch copy and its FAIL output recorded before it enters a committed leaf; a needle with no recorded failure does not ship. |

| T-159-SC | Tampering | npm/pip/cargo installs | low | accept | This plan performs zero package-manager installs. It creates three Node validators using built-ins only. |

boundary.
