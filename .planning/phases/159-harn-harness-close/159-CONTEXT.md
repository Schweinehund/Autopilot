### Area 1 — History mechanism and push choreography (HARN-06)

- **D-01: squash mechanism.** The landing branch reaches `master` as one commit created by plumbing, not by a working-tree merge. `S=$(git commit-tree HEAD^{tree} -p master -F <msgfile>); git update-ref refs/heads/master "$S"; git checkout master`. `[MEASURED]` `master` (`8de413aa`) is an ancestor of the branch, the resulting commit has one parent, `git status --porcelain` is empty after the checkout, and `master^{tree}` equals the branch tip tree by construction. Rejected: `git checkout master && git merge --squash` (opens a 458-file window in which both Stop hooks read Phase-154 planning files) and rewriting history at `9a114815` (141 commits rewritten, 29 of the 31 `fix_sha` rows in Phase 158's binding audit invalidated). — **Reversibility:** one-way once pushed; before the push, `git update-ref refs/heads/master 8de413aa` restores it.
- **D-02: squash timing.** The squash is Task 2 of Plan 159-01, after the leak scrub (D-05) and before everything else. Every later Phase 159 commit is an ordinary commit on `master`, so the pin, the conversion, the leaves, the apex, the workflow and the close-gate are individually reviewable and revertible on the published branch, and the future `V122` pin targets a real close-gate commit. The discuss and plan commits made on the branch ride the squashed tree.
