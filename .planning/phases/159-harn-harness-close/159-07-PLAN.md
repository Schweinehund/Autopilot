## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| apex process to spawned chain members | The apex launches over a hundred child validators and one harness, and its verdict is the sum of theirs. |
| apex process to spawned harnesses | Two harnesses are launched as children, one of which is the newly converted one. |
| archive-root token to the path resolver | A token that only becomes meaningful after archival decides where the apex looks for phase artifacts. |
| nested-flag environment to leg behaviour | An environment variable changes which legs run, so a wrongly-skipped leg is invisible in every nested invocation. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-159-31 | Information Disclosure | a leg that silently skips under the nested flag | high | mitigate | The conversion leg deliberately omits the nested-skip branch, and its real pass is asserted in both a plain and a nested run by two separate acceptance commands that fail on a skip marker. |

| T-159-35 | Tampering | a negative content assertion that silently rots | medium | mitigate | No negative substring assertion about any harness is written; a detector for that pattern is an acceptance command, and the positive-only rule is stated in the plan's prohibitions. |
| T-159-SC | Tampering | npm/pip/cargo installs | low | accept | This plan performs zero package-manager installs. It creates one Node orchestrator that spawns already-tracked scripts. |
