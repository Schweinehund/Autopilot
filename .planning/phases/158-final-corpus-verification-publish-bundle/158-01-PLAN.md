Create `scripts/docs-style/audit-claimed-fixes.mjs`. Node built-in modules only — `node:child_process`,
`node:fs`, `node:path`, `node:os`, `node:crypto`. No dependency is installed and none is imported.

Open the file with a module docstring that states, in prose, that this tool is terminal: it is never
registered as an apex chain member, nothing under `scripts/docs-style/` is read by any validator or
workflow, and Phase 159 either retires it or freezes it. This declaration is the D-07 requirement and
it belongs in the source, not only in a plan.

**Command surface.** Three modes, argv parsed by hand:
- `--rows <path> --log <path>` — audit mode. Read the row file, execute every row's assertions, write
  the captured report to the log path, exit 0 only if every row PASSes and no row is vacuous.
- `--drift <path> --log <path>` — drift-attribution mode. Read a gate-baseline JSON, and for each
  `drift[]` row whose `attributed_to` is a list of SHAs, run `git show --name-only <sha>` and report
  whether that commit touches the row's file. Emit an `unattributed_rows` list. This mode exists so
  plan 158-06 computes that number rather than typing it (D-21); it is written now and exercised there.
- `--self-test` — build fixtures and assert against them; touch no repository file.

**Row schema.** Document it as a JSDoc type comment and validate it at load:
`{ id, source: { kind, ref }, claim, kind, fix_sha, path, evidence_path?, needle, assert: [{ op, value? }], verified_by?, note? }`.
`claim` is at most 200 characters and is redacted for a secret row. `kind` is one of
`corpus-consistency`, `external-fact`, `replace`, `deletion`, `secret`. `source.ref` records a ruling's
identity — a table name and its row's subject — never a line number, because line numbers move.
`needle` is a literal string, never a regular expression, and is `null` for a secret row.
Reject at load, loudly, any row missing a required key or carrying an unknown `op`.

**Range.** The file's top level carries `range` as an object with resolved `from` and `to` SHAs, plus
`authored_at_sha`. Resolve `4e781fc5^..HEAD` once at authoring time and write the pair; the tool reads
the pair and never resolves the token HEAD itself. State in the run log that the log's own SHA is the
**parent** of the commit that records it — literal HEAD equality is unsatisfiable here because the
close-out sequence appends commits after any SHA the phase records.

**The eight ops.** `present_at_parent`, `absent_at_parent`, `present_at_head`, `absent_at_head`,
`count_at_head_eq`, `count_decreased_vs_parent`, `count_increased`, `introduced_then_removed`.
`introduced_then_removed` locates both commits by walking `git rev-list <from>..<to> -- <path>` and
counting per blob; it never uses the pickaxe, because a needle broken across a line wrap is invisible
to it while the fix provably landed.

**The counting instrument.** Two paths, chosen by whether the row's `path` is a directory:
- directory-scoped rows: `git grep -o -F -e <needle> <rev> -- <pathspec>`, counting non-empty output
  lines. Return code 0 means matches, 1 means zero matches, 2 or above throws. Never the `-c` form:
  it sums matching lines, so a line carrying the needle twice counts once — 39 versus 42 on this
  repository's own flagship needle.
- file, wrapped and secret rows: read the blob with `git show <rev>:<file>`, join it into one string,
  collapse every run of whitespace to a single space, then count occurrences in process. This is the
  only form that sees a needle the source wrapped across two lines.

**The mandatory guard.** Before every count, run `git ls-tree -r --name-only <rev> -- <path>` and
require non-empty output. A bad or stale pathspec returns the same return code as a genuine zero-match,
so without this guard a mistyped path reports "confirmed absent" instead of failing loud.

**Vacuity.** After executing a row, reject it if every count it produced is zero, and reject it if the
measured direction contradicts the assertion's direction. Report a rejected row as FAIL with the reason
`vacuous` or `direction`, never as PASS.

**Argv discipline.** Every child-process call is the array-argv form with an explicit `--` terminator
before any pathspec. Pass no option that would route the call through a command interpreter, and never
build a command out of string concatenation. A needle is an array element, never part of a string.

**Secret rows.** A row with `kind: 'secret'` carries `needle: null` and a redacted `claim`. The runner
obtains its literal only from the caller in memory, never from the row file and never from disk; it
never prints the literal into the log, and it never runs the pickaxe for such a row. Its evidence path
is the row's own `path` at the row's `fix_sha`, and it requires exactly one removed content line there;
two or more, or none, is a loud failure rather than a tiebreak.

**Row-set hash.** Compute a SHA-256 over the sorted row ids plus each row's `assert` op list, and print
it as the first line of the run log and store it under `row_set_hash` in the JSON. This is what ties
the log to the committed rows.

**`--self-test`.** Follow `guard-docx.mjs`'s tmpdir fixture shape, extended to a git repository: create
a directory under the OS temp directory, `git init -q` it, set `user.email`, `user.name` and
`init.defaultBranch` so no warning is emitted, and remove the tree in a `finally` block with a force
flag so a Windows pack file cannot leave it behind. Write fixtures carrying both LF and CRLF blobs —
this host normalises to CRLF at system scope and the corpus blobs are CRLF, so a self-test that only
exercises LF proves nothing about the real counting path. Assert four cases and print a
`N passed, M failed` summary line:
(a) a needle present once at the parent and absent at the tip asserts `count_decreased_vs_parent` and
`absent_at_head` and PASSes;
(b) a row every one of whose counts is zero FAILs with the vacuity reason;
(c) a row naming a path that does not exist at the revision FAILs through the ls-tree guard, not
silently as zero matches;
(d) a secret row's literal is absent from every byte the run captured, and the same assertion, re-run
against an in-memory copy into which the literal has been injected, FAILs — proving the check is not
vacuous.
Exit non-zero if any case fails.
