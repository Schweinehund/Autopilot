Extend the library in place. Do not restructure or reformat existing code — `MILESTONE_CLOSE_SHAS`,
`readAtClose`'s body and all 16 existing `readAtVxxClose` exports keep their current text except
for the single try/catch enrichment described below.

**(a) `frozenCause(err)` — exported classifier, defined once (D-28).** It reads the error's stderr
and message, coerces to a string with `String(err.stderr ?? '') + String(err.message ?? '')` so a
Buffer stderr cannot silently fall through, and returns one of three literal values using the
SIX-pattern union — not the two-pattern union the pre-review design assumed:
  - `unreachable-sha` when the text contains `invalid object name`, or `Not a valid object name`,
    or `not a tree object`
  - `absent-path` when the text contains `does not exist in`, or `exists on disk, but not in`
  - `other` otherwise
The second `absent-path` sub-pattern is the realistic production case — a file added AFTER the
frozen SHA emits `exists on disk, but not in` and would have fallen to `other` under a
two-pattern design.

Record two properties as header comments per D-29, so a later reader does not assume them away:
classification is WORKTREE-DEPENDENT (the same call classifies differently in a clean checkout
versus one where the file was deleted), and the taxonomy works today only because every entry in
`MILESTONE_CLOSE_SHAS` is a 7-8 character abbreviation — the library must not assume abbreviation,
because a future full-length pin changes git's message text.

**(b) Attach the typed cause to throws from both readers.** Wrap the `execFileSync` call in
`readAtClose` in a try/catch that, on error, sets `err.frozenCause` to the classifier's result,
PREPENDS a bracketed cause tag to `err.message` in the form `[<cause>] <original message>`, and
RETHROWS. The prepend is mandatory and the position is load-bearing: `check-phase-60.mjs:247`
truncates detail strings at 500 characters, so a cause appended at the end is silently cut off.
This is an enrichment, not a swallow — the error must always propagate.

**(c) `lsTreeAtClose(milestoneTag, dirPrefix, { ext } = {})` (D-34 through D-38).**
  - Reuse the pin gate verbatim: look up `MILESTONE_CLOSE_SHAS[milestoneTag]` and throw before
    spawning anything when it is absent. There is deliberately NO raw-SHA form — a raw-SHA
    signature would bypass the pin gate, which is the module's entire governance value.
  - Invoke `execFileSync('git', ['ls-tree', '-r', '-z', '--name-only', sha, '--', dirPrefix])`
    with `encoding: 'utf8'`, `timeout: 10000`, `stdio: ['ignore', 'pipe', 'pipe']`, an explicit
    `cwd` defaulting to `process.cwd()`, and an explicit `maxBuffer` of `20 * 1024 * 1024`
    mirroring `check-phase-138.mjs`'s `SUBPROCESS_MAX_BUFFER` — a full-tree `-r` already emits
    roughly 203 KB, so the default must not be relied on.
  - `-z` is mandatory: without it git quotes and octal-escapes non-ASCII paths. Split the stdout
    on the NUL character and apply `.filter(Boolean)` — this is part of the decision, not an
    implementer choice: git NUL-TERMINATES the final entry, so a naive split yields a phantom
    empty element and an off-by-one that lands directly on the self-test's exact-count assertion.
  - Apply the `ext` option when supplied, filtering to entries whose path ends with that
    extension. The option exists because every harness call site is a bare `walkMd` loop with the
    only extension filter living INSIDE `walkMd` — omitting `ext` would impose roughly 150 new
    filter edits on Phase 140.
  - Return repo-relative paths. Document in the function's JSDoc that this is NOT a drop-in
    replacement for `walkMd`, which returns absolute paths, so every Phase-140 conversion must
    also strip the `relNormalize` wrapper.
  - Error semantics per D-36: throw on ANY git failure, with `err.frozenCause` attached and the
    cause prepended to the message exactly as in (b). Return `[]` ONLY when git exits 0 with empty
    stdout, which is the valid-but-empty-prefix case. Returning `[]` on failure is forbidden —
    a shallow CI job would enumerate zero files, pass every per-file assertion vacuously, and
    report green while auditing nothing.
  - Add the per-milestone convenience exports mirroring the existing reader exports, one per key
    in `MILESTONE_CLOSE_SHAS`: `lsTreeAtV141Close`, `lsTreeAtV15Close`, `lsTreeAtV16Close`,
    `lsTreeAtV17Close`, `lsTreeAtV17CloseGate`, `lsTreeAtV18Close`, `lsTreeAtV19Close`,
