### ⚠ Anti-regression traps (carry these; they overturn earlier drafts AND locked requirement text)

- **T-1 — Backslashes (B-3).** In JSON `"\\"` **is one literal backslash**. Doubling tracks **JSON string escaping**, not CDATA and not XML. Verified two-sided: `learn.microsoft.com/windows/configuration/start/layout` Win11 pivot ships a **standalone `.json`** (no XML, no CDATA) with **doubled** backslashes, while `assigned-access/configuration-file` Win10 pivot ships **inside CDATA** with **single** backslashes. Therefore: doubled **only inside the `v5:StartPins` JSON string**; **single in every XML attribute** (`<App DesktopAppPath="C:\Windows\system32\cmd.exe" />`). The two forms sit centimetres apart in the same payload. An earlier draft said a single-backslash row is "WRONG" — that is **inverted** and would teach doubling in XML attributes, which genuinely breaks.
- **T-2 — Pandoc list numbering (B-3/A-1).** A column-0 fence inside a numbered list does **NOT** restart numbering. Empirically reproduced twice with the pinned pandoc 3.7.0.2: `pandoc -t native` → `OrderedList ( 3 , Decimal , Period )`; the built `.docx` carries `w:start w:val="3"` and `w:startOverride w:val="3"`. CommonMark likewise emits `<ol start="3">`. Any rule justified by "numbering restarts" is void.
- **T-3 — The `Operational` channel is disabled by default (B-1).** `troubleshoot/windows-client/shell-experience/kiosk-mode-issues-troubleshooting`: *"…can be obtained by **enabling** the `Applications and Services Logs\Microsoft\Windows\AssignedAccess\Operational` channel, **which is disabled by default**"* + *"For some failures, events are only captured once. If you enable logging after an issue occurs … the logs may not capture those one-time events."* A fresh kiosk's channel is EMPTY, which "clean" reads as PASS — a guaranteed false pass. **But do NOT substitute a different channel** — see D3.1. **⚠ Research Concern #4:** these two quotes come from **different H2s** on the same page (*"disabled by default"* under `## Multi-app kiosk issues`; the one-time-events Tip under `## Single-app kiosk issues`). Record both headings and present the caveat as applicable-by-placement — do not imply they are co-located.
- **T-4 — `AppNotFound` is not an event-log entry.** It is `Status`-node status code 2 (`FEATURES.md:29`), and `Status` is the node this milestone already ruled unreadable (`Get`-only; Intune requires Add/Replace/Get; WMI bridge exposes no Status property). It ships **only** as a named prerequisite symptom (KIOSK-05), never as a verification negative.
- **T-5 — `REQUIREMENTS.md:17`'s security-screen claim is FALSE.** `assigned-access/recommendations#keyboard-shortcuts` says only: *"The following keyboard shortcuts aren't blocked for any user account that is configured with a restricted user experience: Alt + F4, Alt + Tab, Alt + Shift + Tab, Ctrl + Alt + Delete."* The page **never mentions a security screen**. Also `Remove-Logoff` → **`Remove Logoff`** (unhyphenated; the hyphenated form reads as a nonexistent PowerShell cmdlet).
  - **⚠ AMENDED by research Concern #6 — T-5 originally over-attributed, and following it verbatim would cause a WRONG EDIT.** `research/FEATURES.md:44` **already** scopes the claim correctly (*"the targeted account has Remove-Logoff applied so Ctrl+Alt+Del reaches the security screen"*) — that is the corrected form, not the defect. At `FEATURES.md:44` edit **the hyphen only**. The false unscoped claim lives at `REQUIREMENTS.md:17` alone.
  - **⚠ AMENDED by research Concern #1 (HIGH) — the replacement sentence I specified is itself partly unsourced.** *"only Ctrl+Alt+Del reaches the security screen"* has **no first-party sentence** behind it: the page never mentions a security screen (which is why T-5 is right) but nothing ties Ctrl+Alt+Del to one either. Under D2.5's own B-6 rule (cite it or cut it) this clause fails. **Ship the fully-sourced rewording instead:** *"…are not blocked for a restricted-user-experience account. Ctrl+Alt+Del is the documented way to exit the kiosk experience, and the profile automatically applies the `Ctrl+Alt+Del Options` policies `Remove Logoff`, `Remove Task Manager` and `Remove Change Password`, which strip those affordances."* Every clause there is verbatim-sourced — see `135-RESEARCH.md` §3.A and Concern #1.
- **T-8 — `AllAppsList` (XSD element) vs `AllAppList` (profile-type name) differ by one `s`** (research Concern #10). Both spellings are correct in their own register — the XSD element is `<AllAppsList>`; Learn's prose, KIOSK-02 and `STACK.md` call the profile *type* `AllAppList`. A reader who writes `<AllAppList>` in the payload ships an unparseable document. Carry one explicit caution line, and make the field-decomposition table use the **element** spelling.
- **T-6 — 22H2 is NOT categorical.** Learn is **silent** on whether Windows 11 21H2 has an equivalent multi-app Start-layout mechanism. `STACK.md:107` rates **v4 = Windows 11 21H2+ [HIGH]** and KIOSK-02 locks a "v4 21H2+" row. Asserting "22H2 is categorical for any Windows 11 multi-app kiosk" overrides a HIGH-rated locked fact by inference-from-silence — `PITFALLS.md:306` Pitfall 20 is the named class.
- **T-7 — The 2017 namespace is the unprefixed ROOT `xmlns`, not a droppable "Windows 10 row", and `default` is not a writable prefix.** Every first-party sample including Windows 11 opens `<AssignedAccessConfiguration xmlns="http://schemas.microsoft.com/AssignedAccess/2017/config" …>`; elements in it are written **bare** (`<Profiles>`, `<AllAppsList>`, `<Taskbar>`). `default` appears only inside the XSD for its own XPath selectors.
