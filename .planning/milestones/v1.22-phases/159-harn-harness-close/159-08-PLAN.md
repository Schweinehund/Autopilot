<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| workflow file to CI runner | A committed YAML file becomes executable instructions on GitHub-hosted infrastructure once it reaches the default branch. |
| third-party actions to the runner | Setup actions for Node and Python execute with the job's permissions. |
| clone depth to frozen object reads | A shallow checkout silently breaks every frozen read, turning real audits into errors or, worse, skips. |
| the sidecar path literal to the governance job | A CI job asserts a string that lives in a source file, and neither side can see the other locally. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-159-36 | Information Disclosure | a shallow checkout silently disabling frozen reads | high | mitigate | Every checkout step pairs one-to-one with a full-depth fetch setting, asserted by a count-equality acceptance command that fails when the two counts diverge. |
| T-159-37 | Tampering | third-party action versions | medium | mitigate | Every action is pinned at a major version already used across the eighteen existing workflows; the newly introduced Python action is additionally pinned at an explicit minor, and its job placement is asserted by a count of exactly three. |
| T-159-38 | Denial of Service | a probe job with a dependency key | medium | mitigate | The probe job's dependency-free requirement is asserted by a scoped scan of that job's own block, and the globbing chain member is run standalone before and after the commit. |
| T-159-39 | Repudiation | a forward-duplicated predecessor apex job | medium | mitigate | A phase-numbered job scan asserts exactly six jobs, all at or above the first content phase of this milestone, so no predecessor apex can be present unnoticed. |
| T-159-40 | Elevation of Privilege | workflow triggers | medium | mitigate | The trigger set is asserted to carry no push trigger, matching every existing workflow; the file is dispatched manually and on a schedule only. |
| T-159-SC | Tampering | npm/pip/cargo installs | low | accept | This plan performs zero package-manager installs. It authors one YAML file that invokes already-tracked Node and Python scripts. |

ASVS level: 1. Blocking threshold: high. The single high-severity entry is mitigated by a computed
acceptance command that compares the checkout-step count to the full-depth-setting count and fails on
any inequality.
