### MATERIALIZED-SET-COUPLING: `withDocsAtClose`'s Materialized Prefix Is a Silent Contract With a Byte-Frozen Validator

**Scope:** `withDocsAtClose` materializes the frozen `docs/**` tree into a temp directory and spawns
`c17-eee-contract.mjs` with `cwd: tmpdir`, leaving the contract validator byte-unchanged (D-11, D-12).
`[MEASURED]` in normal (non-`--self-test`) mode, `c17-eee-contract.mjs` reads nothing outside
`docs/**` — confirmed by source inspection at plan time (`walkMd('docs')`, `readFile` joining
`process.cwd()`, both `c17-fixtures/` reads gated behind `if (SELF_TEST)`). This is a **silent
contract, not an enforced one**: nothing asserts that the materialized set and the contract
validator's own read surface stay in lockstep going forward.

**The hazard, stated concretely.** A future milestone's C17 contract could legitimately grow to read
`docs/_registry/` (registry-row cross-validation) or `scripts/pipeline/filename-map.md` (filename-map
cross-validation) — both plausible extensions of an "EEE document contract" checker — without anyone
touching `withDocsAtClose` or its materialize call sites. Because `c17-eee-contract.mjs` is spawned
against a `cwd` that materializes ONLY `docs/**`, such a read would return `ENOENT` or an empty result
inside the materialized sandbox, and depending on how the contract's own error handling treats that
condition, the read could silently resolve to a pass rather than a loud failure. **All six harnesses
converted this phase would go vacuously green at once** — not one harness, six, simultaneously,
because all six now share the identical materialize call.

**Why not fixed now:** there is no such reading in `c17-eee-contract.mjs` today (confirmed at plan
time), so there is nothing to fix — this is a coupling to record for the future, not a live defect.

**Where it belongs when resolved:** any future milestone that widens `c17-eee-contract.mjs`'s own read
surface beyond `docs/**` must, in the same change, widen `withDocsAtClose`'s materialize call to match
— and should add a structural assertion (a materialized-path allowlist check, or an explicit failure
mode when the contract reads outside the materialized prefix) rather than relying on this document
alone to be remembered.

**Resolution trigger:** the next `c17-eee-contract.mjs` functional change that widens its own read
surface beyond `docs/**`.

**Status:** NEW at v1.21 close. DEFERRED, unowned by any current requirement.
