**A. `scripts/validation/_lib/frozen-at-close.mjs` — two new exports.**

Add `readManyAtClose(milestoneTag, relPaths)` and `createFrozenCorpusReader(milestoneTag,
{ extraPaths })` immediately after `lsTreeAtClose` and its convenience exports. Follow
RESEARCH.md Finding 1's drafted bodies; they are verified against this repo's own objects and
are the specification, not a sketch. Match the module's existing contract exactly, per
PATTERNS.md: pin-gate (`if (!sha) throw`) before any spawn; `execFileSync('git', [argv...])` with
an argument array and the batch input fed on stdin, never interpolated into a shell string;
on failure attach `frozenCause(err)` to `err.frozenCause` and prepend it to the FRONT of
`err.message`, then rethrow unconditionally.

Two constraints are load-bearing and must not be softened:
- Do not pass an `encoding` option to the `cat-file --batch` `execFileSync` call. The result must
  stay a Buffer, and every slice must use `Buffer.indexOf` and `Buffer.subarray` with the byte
  `size` from the frame header, decoding only the already-byte-correct slice. The header field is
  a byte count and this corpus is dense with multibyte punctuation; a decoded-string slice
  desynchronizes at the first such character and corrupts every subsequent file in the batch.
- `createFrozenCorpusReader` must call `lsTreeAtClose` first and `readManyAtClose` second. That
  ordering is what makes an unreachable SHA throw before any blob is requested, and it is why the
  batch reader never has to re-derive an unreachable-SHA cause: `cat-file --batch` exits 0 and
  emits the same missing token for both an absent path and an unreachable SHA, so it cannot
  discriminate — it must never be the thing asked to.

Reuse the existing `SUBPROCESS_MAX_BUFFER` constant. Do not add a persistent or on-disk cache:
each harness runs as its own subprocess and calls the factory once, so the closure-scoped Map is
the whole cache the process ever needs.

| pinned SHA -> assertion outcome | The pin decides which bytes the assertion sees; a wrong pin produces a confident, wrong green or red. |
| harness process -> subprocess (`git`) | Path and SHA values are passed to a spawned binary. |
