# 145-05 FIX-09 SVG Regeneration — Idempotency Evidence

**Purpose:** `grep -rln "docs/diagrams\|\.svg" scripts/validation/` returns nothing — no script under
`scripts/validation/` reads the diagrams directory or any `.svg` file. This means the SVG half of
ROADMAP Success Criterion 5 (the Linux triage diagram was regenerated by its generator, not
text-edited, and the other thirteen diagrams are byte-identical) has **no automated gate anywhere**.
This file is the close evidence for that half of the criterion, recorded per D-47.

`git status --porcelain` cannot be used to prove this: the repository sets `core.autocrlf=true` and
its `.gitattributes` covers only `scripts/pipeline/reference.docx`, so a pure line-ending change on an
`.svg` is absorbed by git's normalisation and never appears as a porcelain diff (D-46). Digest and
`diff -rq` comparison against a pre-run copy is the only sound method.

## Method

```bash
cp -r docs/diagrams /scratch/diagrams-before
md5sum docs/diagrams/*.svg > /scratch/before.md5
python scripts/generate-diagrams.py
diff -rq /scratch/diagrams-before docs/diagrams
md5sum docs/diagrams/*.svg > /scratch/after.md5
```

The one line edited in `scripts/generate-diagrams.py` before running the generator (unmodified
apart from this one line) was the Linux-triage `title()` call's `sub=` argument (the centre-anchored
subtitle at y=58 on a 1200px canvas, not the footer):

```
- "Linux Intune client (Ubuntu 22.04 / 24.04 LTS)  ·  docs/decision-trees/09-linux-triage.md"
+ "Linux Intune client (Ubuntu 24.04 / 26.04 LTS · RHEL 9 / 10)  ·  docs/decision-trees/09-linux-triage.md"
```

## Result

```
diff -rq /scratch/diagrams-before docs/diagrams
Files /scratch/diagrams-before/decision-tree-09-linux-triage.svg and docs/diagrams/decision-tree-09-linux-triage.svg differ
```

Exactly one differing file — the Linux triage diagram. All other 13 diagrams are byte-identical
between the pre-run copy and the post-regeneration output.
