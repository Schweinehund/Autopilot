<objective>
Author the post-conversion guard (`scripts/pipeline/guard-docx.mjs`) that is the SC2 deliverable —
it FAILS on a raw `---` YAML leak in the first ~500 chars of the `.docx` body text and PASSES on a
clean conversion — plus the canonical-invocation wrapper (`convert.ps1`) and the pipeline policy
document (`README.md`) covering the canonical invocation (SC1) and the deployment policy (SC3).

The guard is a verbatim runner-loop clone of `scripts/validation/check-phase-99.mjs` because it is
the Phase-119 seed for `check-phase-113.mjs` (D-07). It stays STANDALONE in `scripts/pipeline/` —
NOT wired into the `scripts/validation/` chain during Phase 113 (D-04/D-07). It imports the D-05
helper from Plan 01; it does not re-implement ZIP walking.

Purpose: The guard is the corpus-safety gate. A false-green guard (raw-byte scan on compressed
`.docx`) would let a leaked or heading-stripped doc pass and corrupt all ~150 docs downstream — the
single HIGH-severity threat of this phase. The decompress-before-scan design plus the dual
clean/leaked self-test assertion is the mitigation.
Output: `scripts/pipeline/guard-docx.mjs`, `scripts/pipeline/convert.ps1`, `scripts/pipeline/README.md`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Converted .docx → guard | untrusted conversion output is inspected before it can reach the corpus/library |
| Guard verdict → corpus | a false verdict propagates to all ~150 docs (the corpus-safety boundary) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-113-04 | Spoofing (false-green) | guard-docx.mjs YAML-leak check | mitigate (HIGH) | The check runs on `extractBodyText()` (decompressed word/document.xml), never raw compressed bytes; the --self-test asserts a deliberately-leaked fixture FAILS (exit 1) AND a direct synthetic-string assertion proves the leak logic fires — a passing leaked fixture is a hard self-test failure |
| T-113-05 | Tampering | guard-docx.mjs heading-style check | mitigate | findHeadingStyleIds requires at least Heading1 on converted output; catches the Pitfall-2 heading-flattening that would flatten the corpus to unindexable text |
| T-113-06 | Denial of Service | guard-docx.mjs self-test pandoc subprocess | mitigate | execFileSync runs pandoc with a bounded timeout and stdio:'pipe'; missing-binary (ENOENT/127) degrades to SKIPPED, never a hang |
| T-113-01 | Tampering | convert.ps1 pandoc version drift | mitigate | convert.ps1 hard-asserts `pandoc --version` == 3.7.0.2 and aborts on mismatch before conversion |
</threat_model>
