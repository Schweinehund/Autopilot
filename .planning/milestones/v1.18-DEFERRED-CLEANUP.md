## CARVE-2 (TOOL-05 Re-Scope): Verify-and-Attest — CLOSED, Logged for Completeness

**Scope:** TOOL-05's original wording ("cache chain-validator subprocess results within a single apex invocation to stop O(n²) cold-spawning") imagined a within-apex redundancy that does not actually exist in the shipped chain-validator architecture. Phase 133 (GA-3, D-06/D-07/D-08) re-scoped the requirement to "verify + attest the existing single-apex O(n) property cross-OS" — and delivered exactly that, with no residual code debt.

**What was verified (Phase 133):** the pre-existing `CHECK_PHASE_NESTED=1` guard already gives the required single-apex O(n) property — each `phaseNum` in an apex's `CHAIN_PHASES` array is spawned exactly once, and `NESTED=1` short-circuits BOTH the recursive chain-guard expansion AND the audit-harness re-run for every nested invocation. There is no within-apex redundancy to memoize, and there was no legal non-frozen apex to edit in Phase 133 anyway (every apex `check-phase-48..128` was frozen at that time; the next new apex, `check-phase-129`, was itself a Phase-134/HARN-12 deliverable, out of Phase 133's scope).

**Why an on-disk cache was explicitly rejected (D-07):** a persisted result cache risks false-pass masking (a stale PASS surviving a subsequent tree change) and would break HARN-13's cross-OS PASS/FAIL/SKIP EXACT-MATCH requirement (a persisted artifact could diverge across the 3 audit axes). An in-process memo would be the theoretically correct *shape* but is a no-op in this architecture, and authoring it would mean editing a frozen apex — itself a D-00a violation.

**Windows cold-clone verification (D-08):** performed as a Phase-133 build step (non-authoritative; Linux GHA stays authoritative per D-03). Phase 134's HARN-13 3-axis re-audit is the FINAL exact-match confirmation of the O(n) claim, not the first place it was checked — and Plan 134-04's Axis 1 fresh-clone run (88 PASS / 0 FAIL / 1 SKIPPED, no deep-nest stall at depth 86) is consistent with the O(n) property holding at v1.18's own deepened chain length.

**Status:** CLOSED at v1.18 (Phase 133, verify-and-attest complete). Logged here per the mandatory `133-CONTEXT.md` dual-carve-out requirement (both CARVE-1 and CARVE-2 must appear in this document), NOT because any open item remains. No further action required. Do not re-open unless a future architectural change to the chain-validator's spawn model reintroduces genuine within-apex redundancy.
