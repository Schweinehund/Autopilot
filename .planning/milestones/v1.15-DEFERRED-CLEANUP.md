## DEFER-119-C: Pandoc YAML-Metadata Alias Trap on Italic `*Previous:` / `*Next step:` Nav Footers (Systemic Conversion Defect)

**Scope:** Converting certain retrofitted `docs/` files through the locked pipeline (`scripts/pipeline/convert.ps1`, pandoc 3.7.0.2) fails with `Error parsing YAML metadata … Unknown alias 'Previous'` (exit 64). Root cause: pandoc's `markdown` reader enables the `yaml_metadata_block` extension, which treats **any** blank-line-preceded `---` … `---` fenced block *anywhere in the document* as YAML. The retrofitted nav-footer shape (a mid-document `---` … `---` pair whose first line is the italic `*Previous:` / `*Next step:` line) is parsed as YAML, where leading `*Word` reads as a YAML **alias reference** → hard exit 64. Files whose footer uses the plain EEE trailer (single trailing `---`, no italic `*Previous/*Next` line — e.g. RE-129) convert cleanly.

**Blast radius (indicative):** all `docs/admin-setup-ios/*` guides tested (RE-107/108/109) fail; the `*Previous:`/`*Next step:` footer is present across the admin-setup guide class and likely other classes. Exact failing count requires a full corpus conversion sweep (not run this milestone).

**Why NOT fixed at v1.15 close:** editing the corpus footers = editing frozen Phase-1 content docs AFTER the predecessor-byte-unchanged gate cleared (119-04); editing the pandoc invocation = editing the frozen PIPE-01 pipeline surface (`convert.ps1`). Both out of scope at the close-gate. The PIPE-02 close pass only needs a *representative* clean-converting `.docx` set, so this did not block 119-06 (the iOS leg was reassigned to RE-057, an iOS L2 runbook that converts clean).

**Where it belongs when resolved (v1.16 — the pipeline/descriptive-filename/structural pass):** candidate fixes: (1) add `--from=markdown-yaml_metadata_block` to the canonical pandoc invocation so mid-document `---` … `---` blocks are thematic breaks, not YAML — **verify it does not regress the top-of-file frontmatter → Word custom-property promotion that OQ4 depends on** (test both); OR (2) normalize the retrofit nav-footer template to a non-alias-leading form (escape the leading `*`, or drop the enclosing `---` pair).

**Resolution trigger (v1.16):** the v1.16 pipeline/structural pass, or when a full-corpus `.docx` conversion sweep is required for a bulk SharePoint upload.

**Estimated effort:** 1-2 plans (invocation fix + regression test, OR corpus-wide nav-footer normalization).

**Status:** NEW at v1.15 close. DEFERRED to v1.16. Systemic conversion defect; does NOT affect the source `.md` corpus or C17 correctness.
