> prerequisites and hard blockers, offboarding and loss of the management plane, and recovery. For
> the domain overview and the routing question of who holds the BIOS secret on Dell, HP and Lenovo

# Lenovo BIOS Configuration Through Intune

Lenovo is the vendor with no vendor cloud connector and no customer secrets of its own to hold.
This guide covers the Think BIOS Config Tool V2 (TBCT V2), the settings tool that reads and writes
BIOS configuration over WMI, and the Lenovo BIOS Certificate Tool V2 (LBCT V2), the password-less
certificate tool — the two Intune-artifact generators that reach Lenovo commercial hardware. Both
tools build ordinary Intune objects that the customer then owns outright; neither tool nor Lenovo
itself holds a copy of the secret afterward. For the routing question of who holds the BIOS secret
on Dell, HP and Lenovo hardware, see
[Firmware and BIOS Governance](00-overview.md#who-holds-the-secret).

The Commercial Vantage Policy Manager, covered under Delivery below, is a client-side PowerShell
interface that deploys a Custom OMA-URI profile. It is not a connector, so the no-connector
statement above stands even accounting for it.

<a id="delivery"></a>
## Delivery

Lenovo is a two-tool vendor, and delivery splits along that line.

### Think BIOS Config Tool V2

Think BIOS Config Tool V2 (TBCT V2) is a PowerShell interface over the `Lenovo.BIOS.Config` module
that reads and writes BIOS settings over WMI. Current as of 2026-04-06: interface v2.0.3, module
v1.0.3. Module and tool names only — no invocation syntax.

**Source:** [Think BIOS Config Tool V2 (Lenovo CDRT)](https://docs.lenovocdrt.com/guides/tbct_v2/)

It produces Intune artifacts directly — Win32 `.intunewin` packages, Remediations scripts, and
direct upload to Intune over the Microsoft Graph API. It requires `IntuneWinAppUtil.exe`, the
Microsoft Graph modules, and tenant permissions.

For supervisor-password changes specifically, Lenovo documents the Win32 app path rather than
Remediations, because the change requires a reboot and the install script exits `3010` to signal
Intune to soft-reboot. Name the exit code as the operational fact it is.

### Lenovo BIOS Certificate Tool V2

Lenovo BIOS Certificate Tool V2 (LBCT V2) is the password-less companion, which generates
cryptographically signed WMI commands. This is the tool the model list belongs to; see Scope below.

Commercial Vantage documents two adjacent Intune routes, neither of which is a BIOS configuration
path in itself: ADMX ingestion into an Imported Administrative templates profile, or the
Commercial Vantage Policy Manager deploying the same policies as a single Custom OMA-URI profile.
This material is search-summary-sourced and was not independently re-fetched this phase, so it
ships here as a brief pointer, not as a procedure.

<a id="authentication"></a>
## Authentication

Two authentication models, and the choice is model-generation-gated.

### Supervisor password

Supplied through an encrypted INI file generated by Think BIOS Config Tool V2 with a passphrase;
the deployment script uses a matching secret key to decrypt. State the custody consequence
plainly, because it is the routing spine: the secret lives in the customer's own Intune package
and key material, never in a vendor cloud.

> Previously created INI files from the HTA version which contain an encrypted password are not compatible with the new Think BIOS Config Tool V2 due to changes in encryption methods.

**Source:** [Think BIOS Config Tool V2 (Lenovo CDRT)](https://docs.lenovocdrt.com/guides/tbct_v2/)

Anyone migrating from the older HTA tool must regenerate every INI.

### Certificate-based BIOS authentication

Replaces the plain-text supervisor password with a digital signing certificate, removing the need
to ship passwords in scripts. Two enrollable certificates, the Supervisor Certificate and the
System Management Certificate, both with reset options in the BIOS menu and with Subject and
Issuer viewable there. No page found this phase states whether those reset options are reachable
without the key-based unlock flow, so this guide does not present them as a bypass for a lost
private key.

**Source:** [Certificate-based BIOS Authentication (Lenovo CDRT)](https://docs.lenovocdrt.com/ref/bios/settings/thinkpad/certbasedbiosauth/)

Then the differentiator:

> Sign commands using keys stored in Azure Key Vault.
>
> Eliminates need to distribute private keys.

**Source:** [Certificate-based BIOS Authentication (ThinkDeploy Blog)](https://blog.lenovocdrt.com/certificate-based-bios-authentication/) — Lenovo CDRT, updated 2025-10-31.

State the consequence in this corpus's own prose, and label the comparative claim as this corpus's
inference exactly as `00-overview.md` already does: Lenovo is the only one of the three vendors
whose signing key can sit in infrastructure the customer owns outright, and therefore under the
customer's own access control, audit logging and key rotation policy. Lenovo makes no such
comparative claim.

Repeated incorrect passphrases can trigger BIOS security lockouts, the same hazard class as HP's,
and Lenovo recommends lab testing before broad deployment. See
[HP BIOS Configuration Through Intune](03-hp-bios-configuration.md).

<a id="scope"></a>
## Scope

Two first-party Lenovo statements about ThinkCentre are both correct, and this section holds them
apart rather than merging them.

Think BIOS Config Tool V2 states its own exclusion:

> This solution currently does not support ThinkCentre desktop products due to incompatible WMI BIOS Interface implementation.

**Source:** [Think BIOS Config Tool V2 (Lenovo CDRT)](https://docs.lenovocdrt.com/guides/tbct_v2/)

The consequence, in a fixed form: a mixed ThinkPad plus ThinkCentre fleet cannot use one tool for BIOS settings.

The certificate tool's model floor is a single sourced sentence, attached to the certificate tool
by name and never to the settings tool: the Lenovo BIOS Certificate Tool V2 supports Lenovo
ThinkPad 2022 and later, ThinkCentre 2020 and later, and ThinkStation 2020 and later with
certificate support.

**Source:** [Certificate-based BIOS Authentication (ThinkDeploy Blog)](https://blog.lenovocdrt.com/certificate-based-bios-authentication/) — Lenovo CDRT, updated 2025-10-31.

Attaching this list to the settings tool is the exact defect BIOS-08 exists to correct, and it is
the defect the milestone research found in the corpus's own earlier record.

Neither page states this reconciliation explicitly, and a fresh search on 2026-08-25 found no page
stating it either way: this corpus's own reading is that the BIOS certificate capability exists on
ThinkCentre 2020 and later, but the settings-configuration tool cannot drive ThinkCentre's WMI
interface. That labeling is what keeps an inference from reading as a vendor claim.

BIOS settings configured through this surface silently gate later OS features: platform
virtualization gates Virtualization-Based Security, which gates Hotpatch and Credential Guard;
Secure Boot gates attestation; and the TPM gates Autopilot attestation. For the failure path when a
firmware setting blocks TPM attestation, see
[TPM Attestation Failure Decision Tree](../../decision-trees/03-tpm-attestation.md).

No per-setting compliance attestation path exists on a Lenovo fleet today; the delivery vehicle
reports what it reports — a Remediation exit code or a Win32 install result — which is coarser
than per-setting reporting.

<a id="prerequisites"></a>
## Prerequisites

Ship Lenovo's own statement first, because it is the Lenovo half of BIOS-06 and Success Criterion
2 grades on the pair reading as a cross-vendor decision point rather than as two disconnected
halves:

> The new Think BIOS Config Tool v2 does NOT set an initial supervisor password

**Source:** [Think BIOS Config Tool V2 (Lenovo CDRT)](https://docs.lenovocdrt.com/guides/tbct_v2/)

Then the fixed literal claim, so this half carries a runnable grep needle rather than a
paraphrase: Lenovo cannot bootstrap an initial supervisor password remotely. The supervisor
password must already be set at imaging or during OOBE, before Intune is involved at all.

Then the inversion, stated explicitly: Dell's native template requires no pre-existing BIOS
password and refuses outright when one exists; Lenovo requires one already set and cannot create
it remotely. See [Dell BIOS Configuration Through Intune](02-dell-bios-configuration.md). The
canonical one-line formulation of this inversion lives in the domain overview; see
[Firmware and BIOS Governance](00-overview.md).

Lenovo's own first-party pointers are bootstrap alternatives and never recovery paths: System
Deployment Boot Mode, and the third-party Remote SVP option Lenovo names from Absolute. Both were
re-confirmed as directly sourced on 2026-08-25. They are for getting a password onto a device that
has none — not for recovering one that is lost.

**Source:** [Certificate-based BIOS Authentication (ThinkDeploy Blog)](https://blog.lenovocdrt.com/certificate-based-bios-authentication/) — Lenovo CDRT, updated 2025-10-31.

The remaining prerequisites:

- The `Lenovo.BIOS.Config` module at v1.0.3 as of April 2026.
- Windows PowerShell or PowerShell Core running with administrative rights.
- `IntuneWinAppUtil.exe`, the Microsoft Graph modules and tenant permissions.
- A reboot for any supervisor-password change, with the install script returning `3010`.
- ThinkCentre is not supported by the settings tool; see Scope above.
- The certificate-authentication hardware floor, again attached to the certificate tool: ThinkPad
  2022 and later, ThinkCentre 2020 and later, ThinkStation 2020 and later.

Survey existing BIOS passwords across the fleet before anything is assigned. For Lenovo the
failure mode is the third of three: Dell refuses outright, HP retries until the BIOS locks out,
and Lenovo simply cannot create the password at all. See
[HP BIOS Configuration Through Intune](03-hp-bios-configuration.md).

<a id="offboarding"></a>
## Offboarding and Loss of the Management Plane

Lenovo has no vendor management plane to lose. There is no vendor cloud connector to deactivate,
no vendor-held vault to expire, and no vendor-side countdown, because the secret never leaves the
customer's control in the first place. What the customer can lose is their own material — the
encrypted INI file and its passphrase, or the certificate private key — and that loss is governed
by the customer's own backup, access-control and key-rotation practice, not by a vendor's account
lifecycle.

This is a structural absence, not a documentation gap, so a reader does not read the short section
as an omission. The heading is present here because it is D-01's own justification for the
six-section shape holding across all three guides, and omitting it would break the identical shape
Success Criterion 1 grades.

The cross-vendor contrast: in Dell and HP, losing the management plane loses the secret — Dell's
subscription end and HP's 30-day countdown. See
[Dell BIOS Configuration Through Intune](02-dell-bios-configuration.md) and
[HP BIOS Configuration Through Intune](03-hp-bios-configuration.md). In Lenovo, there is no
management plane between the customer and the secret, which is the same fact the domain routes on.

Because the artifacts are ordinary Intune objects the customer owns — Win32 apps, Remediations
scripts, a Custom OMA-URI profile — removing Lenovo's tooling from the process leaves those
objects in the tenant exactly as any other Intune object, and they are removed the same way. There
is no vendor-side orphaning behavior to account for.

<a id="recovery"></a>
## Recovery

Two cases with two different answers. They are held apart deliberately, because letting the
answer to one read as the answer to the other is the exact defect this section must avoid.

### Supervisor password lost — a documented, destructive path

> Reset forgotten supervisor password - If you forget your supervisor password, Lenovo cannot reset your password. You must take your computer to a Lenovo Service Provider to have the system board replaced.

**Source:** [Types of password for ThinkPad (Lenovo Support, ht036206)](https://support.lenovo.com/us/en/solutions/ht036206-types-of-password-for-thinkpad) — published 2015-06-09, retrieved 2026-08-25.

There is no software reset path, so on a Lenovo fleet the supervisor password is not a recoverable
secret and must be backed up as if it were irreplaceable. This is Lenovo's general ThinkPad
password statement; as of 2026-08-25 no page found states a different escalation path for devices
managed through the settings tool.

Escalate to Lenovo support, and stop. This corpus does not carry Dell's own escalation specifics
across to Lenovo; nothing sources that Lenovo requires or accepts them.

### Certificate private key lost — a documented silence

(a) What Lenovo does document for this specific gap: the certificate-based BIOS authentication
reference page documents the enrollable Supervisor and System Management certificates and their
BIOS-menu reset options, with Subject and Issuer viewable locally. No page found this phase states
whether those reset options are reachable without the key-based unlock flow, and this guide does
not present them as a bypass. Certificate reset does not stand as an answer for the
supervisor-password case above — a reader who arrives having lost a password must not read a path
that does not exist for them.

(b) The explicit statement of the absence, with the pages checked named here: as of 2026-08-25,
Lenovo's certificate-based BIOS authentication reference, the Lenovo BIOS Certificate Tool
getting-started guide, and the full certificate-module cmdlet reference were all read, and none
documents recovery, reset or bypass for a lost private key. Every mutating operation in the
cmdlet reference requires the private key or a key-vault reference, and no bypass operation
exists.

(c) Escalate to Lenovo support, and stop.

Storing the signing key in Azure Key Vault means the key inherits that service's own soft-delete
and purge-protection model rather than living as a file on an administrator's workstation — this
is this corpus's own inference, not a Lenovo claim.

No board-replacement sentence ships for this second case. Lenovo has said nothing about it, and
the bar against inventing one stands unchanged here even though it moved for the password case
above.

<a id="unsupported-callouts"></a>
## Unsupported and Anti-Feature Callouts

These are documented absences in the surface itself, not misconfigurations an administrator can
correct.

**DFCI is unavailable on Lenovo hardware, not declined.** Lenovo appears on none of the DFCI
manufacturer lists this corpus tracks. See
[Device Firmware Configuration Interface (DFCI)](01-windows-dfci.md) for that surface and its own
OEM list.

**The settings tool cannot drive ThinkCentre.** See Scope above.

**The settings tool cannot create an initial supervisor password.** See Prerequisites above.

**No per-setting compliance attestation path exists on a Lenovo fleet.**

**There is no partner-portal surface in the Intune console for Lenovo.** As of 2026-08-25, Lenovo
ships no vendor cloud connector, so there is no partner-portal discovery surface for it to appear
on, unlike Dell's Management Portal and HP Connect.
